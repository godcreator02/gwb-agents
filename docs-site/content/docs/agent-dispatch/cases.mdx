**本页回答**：两条真实链路一步步怎么走。案例一是主人在 QQ 私聊里用组命令把一件事派到协作项目，结果回私聊；案例二是协作站的新通知到主人手机。

## 案例一：私聊里发 /mmc，agent 在协作项目里干活

前提（一次性）：协作站项目列表里的这个项目起了 QQ 命令 `/mmc`（`collab.project.qq-command`），协作站经 `gwbQqBot.registerTaskGroup` 注册一个任务组：命令 `/mmc`，标题是这个项目的站名，工作区是项目文件夹（协作仓的上一级，agent 能看到同一个项目里的协作仓、资料库与代码仓），组的要求三行：

{/* ref file="../../../oz47p-docsite-kit/god-docsite/plugins/collab/src/project/qq-task-groups.ts" lines="29-38" hash="669ad24a1341" blob="0f91c5665e07" */}

这个组白名单里的每个私聊都能用，各记各的会话。

1. **入站**：主人私聊发「/mmc 把仿真步长改成 1µs」。发言人在白名单里、消息 id 没见过；第一段 `/mmc` 和插件注册的组完全相同，正文进这个私聊里 mmc 这一组的队列
2. **派一轮**：mmc 组没有在做的一轮，就从队列取出这条，定下会话（复用上一个，或空闲超时后新开），调 `gwbClaudeAgent.create`（续会话是 `send`），拿回会话号与轮次存进这一组的状态，回「【mmc】已接收，开始做。」
3. **agent 干活**：claude-agent 在项目文件夹里开这一轮。agent 照组的要求先读说明书 collab：说明书要求提交之前先把改动给人看，所以从 QQ 派来的这一轮把改动写进最后一条回复，人在同一组里回复确认，下一轮再经 `collab.submit` 提交审核
4. **等结束**：qq-bot 调 `waitRound` 等这一轮结束，拿到最后一条回复与用的模型
5. **回私聊**：结果开头写「【mmc · 第 N 轮 · 模型】」，引用派出这一轮的那条消息；还在 60 分钟窗口里就被动回复，过了改主动消息，都发不出去就记进没送达，等主人发 `/状态` 时补发：

{/* ref file="../../gwb-qq-bot/plugins/qq-bot/src/dispatch/chat-rounds.ts" lines="354-370" hash="cc38654cbace" blob="6a2e3cf91455" */}

6. **下一轮**：mmc 组的队列里还有就接着开下一轮；这期间主人直接发的文字进默认组，照常派出，不排在 mmc 后面

这条链在 qq-bot 的单元测试里走过（`plugins/qq-bot/tests/rounds.test.ts` 的「一轮：派出、等结束、发回最后一条回复」），用协作站注册的组在真实机器人上端到端走过没有，没有记录。

## 案例二：协作站出现新的合并请求，私聊主人

1. **状态变了**：协作站某个项目的哪样状态变了（同步、合并请求、issue 等），这次加载后做完过一次完整刷新，就把这个项目此刻的全部通知交给通知渠道：

{/* ref file="../../../oz47p-docsite-kit/god-docsite/plugins/collab/src/notifications/project-notifications.ts" lines="80-87" hash="64d75a41b292" blob="456019e4bd7c" */}

2. **挑新的**：QQ 私聊这份实现对照这个项目记下的已发 id，只挑新出现的；自己保存出来的改动不发；这一批里有检查出错的通知时，一个已发 id 都不去掉（读 Gitea 失败时合并请求看起来像消失了，等连上再出现不能当成新的重发）
3. **等满 60 秒**：新出现的那几条一起开一个计时器；期间消失过的就不发，再出现时从头等。等待中的只在内存里，重启后从头等
4. **发通知**：到点时还在的几条合成一条，首行是 `协作站 <项目名>`、每条通知一句，截到 600 字；id 由项目、这批通知与此刻算出，经 inject 的 `gwbQqBot.notify(id, text)` 发出；没装 qq-bot 就只记一行警告：

{/* ref file="../../../oz47p-docsite-kit/god-docsite/plugins/collab/src/notifications/qq-private-chat.ts" lines="161-177" hash="186b3202f88b" blob="fcc474a74e72" */}

5. **qq-bot 去重**：同 id 同内容回 `duplicate`，同 id 不同内容拒绝；前提是设置了 `owner-openid` 且在白名单里
6. **主动私聊**：走主动消息接口，不受被动回复窗口限制，受平台频控与用户开关影响
7. **发不出去不重发**：通知还在协作站网站的提示栏里；一条通知消失后再出现，算新的一件事，会再发
