**本页回答**：这套架构的每条决策、被否掉的方案与理由。每条的来龙去脉在对应的轨迹卡里，推后的事在[路线](/future/roadmap)。

| 决策 | 内容 | 否掉的方案与理由 |
| --- | --- | --- |
| 只按真实场景设计 | 模块与接缝只为[六个场景](/docs/agent-dispatch)切，场景里没有的能力不做（[轨迹卡](/trajectory/2026-10-06-rebuild-from-real-scenarios)）；qq-bot 只处理私聊以后，协作项目的场景改成私聊里用组命令派（[轨迹卡](/trajectory/2026-10-08-private-chat-scenarios)） | 在旧代码上逐处修补：票据哈希、任务簿交叉校验、派单未确认与人工解除这些机制没有一个对应真实场景，修补只会让它们继续互相牵制 |
| 服务是本体、命令是薄封装 | 插件之间经 cordis 服务调用，依赖方可选 inject；命令只给进程外调用方，校验参数后调同一个服务方法（[派单走服务](/trajectory/2026-10-07-dispatch-via-services)、[服务是本体](/trajectory/2026-10-07-service-is-the-body)） | 插件之间按名字调命令：拿不到类型，提供方装卸、重载时调用方不知道，错误只能靠字符串前缀辨认 |
| 执行端插件只做 agent 本体 | gwb-zcode、gwb-claude-agent 各按自己那个 agent 的样子给方法，不管占用、不管回报、不认识任何应用 | 让几个执行端同形：ZCode 有侧栏、窗口、归档，claude-agent 每轮一次 `query()`、只交回最后一条回复，压成一个形状要么丢能力，要么谁都不合身 |
| qq-bot 只接 claude-agent | 任务一律交给 claude-agent，qq-bot 没有执行端适配层；模型是 claude-agent 的设置 `default-model`，qq-bot 不选。10-06 的[适配在应用](/trajectory/2026-10-06-adapters-stay-in-apps)是当时有两个执行端时的决定，已被这一条取代（qq-bot 仓轨迹卡「执行统一交给 claude-agent」） | 在 qq-bot 里选执行端与模型：用户要的是改一项配置，不集成进 qq-bot。只接一个执行端的代价是以后要接别的，得重新加回「这一组交给谁」 |
| 不锁工作区 | 执行端插件不登记占用，同一个工作区可以同时跑几条会话；qq-bot 两个任务组指向同一个目录也同时做（[轨迹卡](/trajectory/2026-10-06-no-workspace-lock)） | 底层占用表：主会话批量派活就是同一目录 5 条并行，占用表把它挡死；会不会改到同一个文件，只有拆任务的人知道 |
| qq-bot 只处理私聊 | 群事件只记事件类型；每个人在自己的 home 里配自己的机器人，通知与派任务都走私聊（qq-bot 仓的轨迹卡「只处理私聊」） | 群功能留着不用：要一直维护群的被动窗口、回执格式与查自己在群里身份的接口，而协作站已经不需要群 |
| 私聊按命令分任务组 | 直接发的文字进默认组，「/组命令 正文」进那个组；每个私聊的每个组各有会话与队列，同一组一次一轮，不同的组可以同时做（qq-bot 仓的轨迹卡「按命令分任务组」） | 一个私聊只有一个会话：日常的事和协作项目的事挤在同一个会话里，上下文互相干扰，一件慢的事挡住别的 |
| 发回最后一条回复 | qq-bot 派出后调 `waitRound` 等这一轮结束，把最后一条回复原样发回；提示词要求它用 markdown、5000 字以内。10-06 的[回报简化](/trajectory/2026-10-06-simple-round-report)已被这一条取代（qq-bot 仓轨迹卡「去掉回报命令，发回最后一条回复」） | agent 做完自己调 `qq-bot.report`：要靠 agent 记得调，没调就得等人发 `/状态` 时问一次执行端才收尾 |
| 交给 AI 只给提示词 | `collab.ai.prompt` 把一个项目的全部通知写成提示词交回原文，人在协作窗格或网站提示栏点「复制给 AI」，自己贴给想用的 AI；插件不启动任何 AI（god-docsite 仓提交 7955830e） | 协作站自己开 ZCode 会话或新开 Claude 终端窗口（10-08 时的做法）：改的理由没有记录 |
| 协作站 → qq-bot 单向，协作站注册任务组 | 协作站 inject `gwbQqBot` 发通知、按项目注册任务组；qq-bot 里没有和协作站有关的代码（[轨迹卡](/trajectory/2026-10-08-collab-registers-task-groups)） | ① 双向依赖：两个插件的 peer 成环，devkit 发版检查直接拒绝；② qq-bot 保留绑定上的「协作仓」标记：qq-bot 要认识协作站的规矩 |
| 通知只发新出现的，不重发 | 协作站每个项目记下发过的通知 id，只发新出现、连续存在满 60 秒的；qq-bot 按 id 去重，发不出去不重发 | 待发标记加送达回执：多一份状态要对齐，而通知本来就在协作站网站的提示栏里 |
