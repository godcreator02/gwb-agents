**本页回答**：`plugins/claudecode` 负责什么、对外给什么、依赖谁，以及刻意不做的事。

## 功能

每一轮启动一个本机 Claude Code 原生 CLI 进程（`claude -p`），用 stdin 交提示词，从流式 JSON 里只认这条会话的 `result` 一行当这一轮的回答，进程退出就是这一轮结束。
启动后立即交回会话 ID，结果到达不靠定时轮询。同一个工作区可以同时开几条会话。

## 接口

本体是服务 `gwbClaudecode`，别的插件 inject 它调方法；`claudecode.*` 命令给 agent 用，只查参数形状、再调同名方法。类型在本包 `src/api.ts`：

{/* ref file="../plugins/claudecode/src/api.ts" lines="37-48" hash="53b8a37086d0" blob="716910530c3d" */}

| 方法 / 命令 | 参数 | 作用 |
| --- | --- | --- |
| `create` / `claudecode.create` | `{workspace,prompt}` | 新建 UUID 会话并启动第一轮，返回 `{sessionId,round,accepted:true}`，只表示进程启动了 |
| `send` / `claudecode.send` | `{workspace,sessionId,prompt}` | 等这条会话上一轮的进程退出，再用原生 `--resume` 续一轮 |
| `status` / `claudecode.status` | `{workspace,sessionId}` | 读进程事件保存的状态：`running` 以外都是这一轮结束了，`completed` 带最终回答，`failed` 带原因 |

工作区必须是绝对路径；续聊与查询只认本 home、同一个工作区的会话。

**中断的轮次一律记失败，没有「状态不明」**：插件卸载时结束在跑的进程，那一轮记 `failed`；上次工作台没正常退出、记录里留着的 `running`，读回时同样按中断失败收尾，之后可以照常续聊：

## 不做的事

- **不管占用**：同一个工作区开几条会话由调用方决定（轨迹卡[「删掉占用表」](/trajectory/2026-10-07-drop-workspace-occupancy)）
- **不参与回报**：要不要回报、报给谁由派任务的一方写进提示词；本插件不认识任何上层应用、不保存凭证，回答原样保存
- **不自动重发**：中断的轮次记失败，由调用方决定要不要再派
- **不把进程启动当成任务完成**；权限模式按用户授权固定为 `bypassPermissions`，不改全局配置
