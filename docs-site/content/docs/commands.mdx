**本页回答**：五条命令各收什么参数、回什么、什么情况下报错。派任务的两条 `effect` 是 `external`：指令经 ZCode 发给外部的模型服务，ZCode 还会以完全访问权限改本机文件；
`zcode.open` 改 ZCode 窗口显示的工作区，标 `write`；`zcode.status` 不改数据，但同样要临时打开 ZCode 主进程的调试端口，标 `write`；`zcode.archive` 改 ZCode 的任务索引，标 `write`。

一次派任务的流程：要让人在侧栏里看见就先 `open` 那个目录 → `create`（或 `send`）拿到 `taskId` → 隔一阵 `status`，直到 `roundIsOver` 为 `true` → 不再用的会话 `archive`。

## zcode.open

把 ZCode 窗口切到一个工作区。侧栏只显示当前工作区的会话：`zcode.create` 在哪个目录建会话，人就要切到哪个目录才看得见。

{/* ref file="../plugins/zcode/src/args.ts" lines="70-74" hash="4b8567404440" blob="dad04a3d67e9" */}

| 参数 | 必给 | 说明 |
| --- | --- | --- |
| `workspace` | 是 | 工作区目录的绝对路径，要已存在 |

回 `{ workspace, switched }`：`switched` 为 `false` 表示窗口本来就在这个工作区，没有动。路径比较不分大小写、不管结尾的分隔符。

## zcode.create

在一个工作区里新建会话、切到完全访问、发出任务，等这一轮在 ZCode 里开始了就交回。

{/* ref file="../plugins/zcode/src/args.ts" lines="51-58" hash="e23579e3b56a" blob="dad04a3d67e9" */}

| 参数 | 必给 | 说明 |
| --- | --- | --- |
| `workspace` | 是 | 工作区目录的绝对路径，要已存在。ZCode 在这个目录里执行任务，侧栏里会话归在这个工作区下 |
| `prompt` | 是 | 任务说明，非空 |

## zcode.send

在已有会话里接着发指令。`task` 是 `zcode.create` 回执里的 `taskId`，`workspace` 写建它时的那个目录；发之前同样切到完全访问——
人在界面上把模式改过了也会被切回来。

{/* ref file="../plugins/zcode/src/args.ts" lines="60-68" hash="7df4d05e2c98" blob="dad04a3d67e9" */}

两条派任务的命令回执相同：

{/* ref file="../plugins/zcode/src/index.ts" lines="17-19" hash="574bd9a6514f" blob="f9305d9c6595" */}

| 字段 | 说明 |
| --- | --- |
| `taskId` | 会话 id（`sess_` 开头），之后给 `zcode.status` 与 `zcode.send` |
| `title` | 侧栏里显示的标题，ZCode 自己起，可能在第一轮之后改 |
| `status` | ZCode 的任务状态，刚发出时通常是 `running` |
| `mode` | 代理进程实际用的权限模式，总是 `yolo` |
| `roundStarted` | `false` 表示 30 秒内这一轮还没开始（多半排在还在跑的上一轮后面），这时 `zcode.status` 读到的仍是上一轮 |

## zcode.status

读一个会话最新一轮（最后一条用户消息之后）的进度与回答。

{/* ref file="../plugins/zcode/src/args.ts" lines="85-102" hash="e8a24168ac6a" blob="dad04a3d67e9" */}

| 参数 | 必给 | 说明 |
| --- | --- | --- |
| `workspace`、`task` | 是 | 同 `zcode.send` |
| `waitSeconds` | 否 | 缺省 0 立即交回；给了就最多等这么久（0 到 240），做完提前交回 |
| `replyTailChars` | 否 | 正整数：只交回回答末尾这么多个字符；缺省全部交回 |

ZCode 会把这一轮的工具调用记录（工具名、输入、输出）也写进回答，看图、读长文件多的一轮，一条回答就有几万字，
超过 MCP 入口单次返回的上限（40000 字符），整个回执交不回来。收尾的总结在最后，所以截的是末尾：从最后一条回答往前留，
合计不超过 `replyTailChars`，越过上限的那一条只留它的末尾，再往前的整条省掉。

{/* ref file="../plugins/zcode/src/task-progress.ts" lines="93-108" hash="0ed3b2279759" blob="4e0b14d7e847" */}

| 字段 | 说明 |
| --- | --- |
| `roundIsOver` | `true` 才是这一轮停下了：做完、失败，或停在等人确认 |
| `status` | ZCode 的任务状态：`completed`、`idle` 是正常结束，`failed`、`error`、`cancelled` 是失败，`running` 还在跑；没发过指令的会话是 `null` |
| `replies` | 这一轮的回答，按出现顺序；没做完时是写到一半的内容 |
| `omittedReplyChars` | 按 `replyTailChars` 省掉的字符数；没给这个参数或没省是 0 |
| `mode` | 代理进程实际用的权限模式 |
| `fileChanges` | ZCode 记录的文件改动，原样带回 |
| `pendingPermissions` | 非空表示停在等人确认，要去 ZCode 界面处理 |

## zcode.archive

把一个会话从 ZCode 侧栏的会话列表里收起来，记录不删，在 ZCode 的已归档列表里还看得到。参数 `workspace`、`task` 同 `zcode.send`，
只是 `workspace` 那个目录已经删了也行：它只是 ZCode 记会话用的键，归档不在目录里执行任何东西。

{/* ref file="../plugins/zcode/src/args.ts" lines="76-83" hash="4ac2a0ca4267" blob="dad04a3d67e9" */}

回 `{ taskId, title, archived: true }`。还在跑（`status` 为 `running`）的会话直接报错，等 `zcode.status` 的 `roundIsOver` 为 `true` 再归档；
已经归档过的再调一次照样成功。

## 报错

命令执行失败时回 `ok: false`（经 MCP 入口是 `isError` 的文本），原因写在文本里：

| 原因文本里有 | 怎么办 |
| --- | --- |
| `不认识参数`、`缺 …`、`要是绝对路径`、`不是已存在的目录`、`waitSeconds`、`replyTailChars` | 照文本改参数 |
| `zcode.status` 的返回超过单次返回的上限 | 带上 `replyTailChars`（如 20000）再调 |
| `应有一个 ZCode 主进程` | ZCode 没开，或开了多个实例：请用户打开或关掉多余的 |
| `应有一个 ZCode 工作区窗口` | 请用户关掉多余的 ZCode 窗口 |
| `找不到 services.…`、`快照形状不对`、`没有 settings.mode.current`、`没回 taskId`、`activeWorkspacePath 应有一个值` | ZCode 升级改了内部结构，插件要跟着改 |
| `秒后窗口的工作区仍是` | ZCode 没按启动参数切过去，可能改了启动参数的处理；请用户手动切 |
| `切换到完全访问 … 后代理的模式是` | 模式没切成，指令没发出 |
| `还在跑，等这一轮做完 … 再归档` | 用 `zcode.status` 等它做完再 `zcode.archive` |
| `调过 archiveTask 之后不在 … 的已归档列表里` | `workspace` 不是建这个会话时的目录，或 ZCode 改了归档的做法 |
| `调试协议请求 … 无响应` | 先去 ZCode 侧栏看指令有没有发出去，再决定要不要重调 |
