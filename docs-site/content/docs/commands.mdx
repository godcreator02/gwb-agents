**本页回答**：两条命令各收什么参数、回什么、什么情况下报错。两条的 `effect` 都是 `external`：指令经 ZCode 发给外部的模型服务，ZCode 还会以完全访问权限改本机文件。

## zcode.create

在一个工作区里新建会话、切到完全访问、发出任务，等这一轮做完交回。

{/* ref file="../plugins/zcode/src/args.ts" lines="49-57" hash="1b3fe2767248" blob="601ee5a11cce" */}

| 参数 | 必给 | 说明 |
| --- | --- | --- |
| `workspace` | 是 | 工作区目录的绝对路径，要已存在。ZCode 在这个目录里干活，侧栏里会话归在这个工作区下 |
| `prompt` | 是 | 任务说明，非空 |
| `timeoutSeconds` | 否 | 最多等多少秒，缺省 1800；到点先交回，任务不取消 |

## zcode.send

在已有会话里接着发指令。`task` 是 `zcode.create` 回执里的 `taskId`，`workspace` 写建它时的那个目录；发之前同样切到完全访问——
人在界面上把模式改过了也会被切回来。

## 回执

两条命令回执相同：

{/* ref file="../plugins/zcode/src/index.ts" lines="14-17" hash="1852fcf2285b" blob="aacae79c0995" */}

| 字段 | 说明 |
| --- | --- |
| `taskId` | 会话 id（`sess_` 开头），续上时给 `zcode.send` |
| `title` | 侧栏里显示的标题，ZCode 自己起，可能在第一轮之后改 |
| `status` | ZCode 的任务状态：`completed`、`idle` 是正常结束，`failed`、`error`、`cancelled` 是失败 |
| `mode` | 会话的权限模式，应当总是 `yolo` |
| `replies` | 这一轮新出现的回答，按出现顺序；中间几条往往是干活过程中的说明，最后一条是收尾的话 |
| `fileChanges` | ZCode 记录的文件改动，原样带回 |
| `pendingPermissions` | 非空表示停在等人确认，要去 ZCode 界面处理 |
| `timedOut` | 为 `true` 时到了 `timeoutSeconds` 还没做完，ZCode 还在跑 |

## 报错

命令执行失败时回 `ok: false`（经 MCP 入口是 `isError` 的文本），原因写在文本里：

| 原因文本里有 | 怎么办 |
| --- | --- |
| `不认识参数`、`缺 …`、`要是绝对路径`、`不是已存在的目录` | 照文本改参数 |
| `应有一个 ZCode 主进程` | ZCode 没开，或开了多个实例：请用户打开或关掉多余的 |
| `应有一个 ZCode 工作区窗口` | 请用户关掉多余的 ZCode 窗口 |
| `找不到 services.zcodeTaskService`、`快照形状不对`、`没回 taskId` | ZCode 升级改了内部结构，插件要跟着改 |
| `切换到完全访问 … 后读回的模式是` | 模式没切成，指令没发出 |
| `调试协议请求 … 无响应` | 先去 ZCode 侧栏看指令有没有发出去，再决定要不要重调 |
