**本页回答**：这个仓里反复出现的词各指什么。

| 词 | 意思 |
| --- | --- |
| ZCode 桌面端 | 本机装的 ZCode 客户端程序（Electron），一个主进程加若干渲染进程与会话进程 |
| 会话 / 任务 | ZCode 侧栏里的一条，id 以 `sess_` 开头；ZCode 内部两个叫法混用，本仓命令参数叫 `task`、回执叫 `taskId` |
| 代理进程 | 每条会话背后跑模型、调工具的进程（`zcode.cjs app-server`）；它实际用的模式记在自己的设置里，可能和界面显示的不一样 |
| 一轮 | 发出一条指令到 agent 做完它之间的过程。ZCode 的回执只带这一轮新出现的回答；qq-bot 的一个任务组一次只做一轮，从派出到最后一条回复发回为止 |
| 完全访问 | ZCode 界面上的一种权限模式，内部值 `yolo`：改文件、运行命令都不先问人 |
| 变更前确认 | ZCode 界面上的另一种权限模式，内部值 `build`：改文件前停下等人确认；新建会话默认是它 |
| 工作区窗口 | ZCode 打开一个工作区目录的那个窗口；插件只认恰好一个的情形 |
| 调试端口 | Chromium 远程调试端口 9339，ZCode 带 `--remote-debugging-port=9339` 启动才有，连上后能在工作区窗口的页面里执行脚本 |
| 归档 | 把会话从侧栏的会话列表里收起来，记录不删，ZCode 的已归档列表里还看得到 |
| 侧栏 | ZCode 窗口左边列出会话的那一栏；CLI 无界面跑出来的会话不在这里 |
| 接缝 | 两个模块之间跨边界的那条关系：连着哪两端、中间传什么、哪边负责。接缝图上就是带编号的线 |
| 执行端插件 | gwb-zcode、gwb-claude-agent：各自把一种 agent 做成服务（`gwbZcode`、`gwbClaudeAgent`），同名命令是给 MCP 的薄封装；不认识任何应用 |
| 执行端 | 进程外跑 agent 的那头：ZCode 桌面端、claude-agent 启动的 Claude Code 进程 |
| 服务是本体 | 插件之间经 cordis 服务调用、依赖方 inject；命令只是给进程外调用方的薄封装，校验参数后调同一个服务方法 |
| 任务组 | qq-bot 里的一个工作区：私聊里用斜杠命令把任务派给它，交给 claude-agent 做；每个私聊的每个组各有会话与队列。来源有三种：每个私聊的默认组、命令登记的组、插件注册的组 |
| 聊天表 | qq-bot 存状态的那份表：每个私聊一行，行里按任务组各记会话、在做的一轮与队列，另记默认组的绑定、没送达的结果、命令登记的任务组；一个机器人一份 |
