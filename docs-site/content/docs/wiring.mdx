**本页回答**：gwb-zcode 提供哪些服务、命令与说明书；注入了哪些服务、是必需还是局部注入、peer 怎么写；和 ZCode 桌面端靠哪些约定通道连着。

## @godcreator/gwb-zcode

### 提供

| 类别 | 名字 | 说明 |
| --- | --- | --- |
| 服务 | `gwbZcode` | 本体：`open` / `create` / `send` / `status` / `archive`。别的插件 inject 它；类型在本包 `dist/index.d.ts`，给 cordis `Context` 补了这一项 |
| 命令 | `zcode.open` / `zcode.create` / `zcode.send` / `zcode.status` / `zcode.archive` | 给 agent 的薄封装：只查参数形状、再调同名服务方法，形状见[命令](/docs/commands) |
| 说明书 | `zcode` | 包根 `skills/zcode/`，经 `gwbSkills.register` 登记 |

不注册窗格、不声明设置项。不参与回报、不管占用，和上层应用之间没有任何约定的错误措辞。现在 inject `gwbZcode` 的是 qq-bot 与协作站各自的执行端适配层。

### 注入

| 服务 | 提供方包 | 必需 / 局部注入 | peer 写法 | 用来做什么 | 缺了会怎样 |
| --- | --- | --- | --- | --- | --- |
| `gwbCommands` | `@godcreator/gwb-commands` | 必需（顶层 `inject`） | `^0.6.0` | 登记命令 | 插件不加载 |
| `gwbSkills` | `@godcreator/gwb-skills` | 局部注入 | `^0.4.7`，可选 | 登记说明书 `zcode` | 照常加载；agent 读不到说明书 |

内核包 `@godcreator/gwb-kernel-desktop`（`^0.10.1`）只提供接口类型；`cordis`（`^4.0.0-rc.10`）提供服务基类 `Service`，按值 import，所以写进 peer。

### 按名字调用与约定通道

全部是 ZCode 的内部结构，没有兼容承诺，ZCode 升级后最先要核对的就是这张表。

| 通道 | 对方 | 名字 | 用来做什么 |
| --- | --- | --- | --- |
| 进程命令行 | ZCode 主进程 | 不含 `--type=`、`zcode.cjs`、`windows-helper` 的 `ZCode.exe` | 认出主进程，读它的 `ZCode.exe` 路径 |
| 启动参数 | ZCode 主进程 | 命令行里有 `--remote-debugging-port=9339` | 没有就报错，写明怎么带着它重开 |
| 本机端口 | ZCode 工作区窗口 | `127.0.0.1:9339`，Chromium 远程调试协议，`/json/list` 列出页面 | 直接在窗口的页面里执行脚本 |
| 页面地址 | ZCode 工作区窗口 | 类型 `page`、地址含 `/out/renderer/index.html` | 认出工作区窗口 |
| React 树 | ZCode 工作区窗口 | `memoizedProps.services.zcodeTaskService` / `zcodeAgentService` | 拿到客户端的任务服务与代理服务 |
| 服务方法 | `zcodeTaskService` | `createTask`、`setMode`、`sendPrompt`、`getTaskSnapshot` | 建会话、切模式、发指令、读快照 |
| 服务方法 | `zcodeTaskService` | `archiveTask`、`listArchivedTasks` | 归档会话、读回已归档列表核对 |
| 服务方法 | `zcodeAgentService` | `readSession` | 读代理进程实际用的模式 |
| 服务方法 | `zcodeAgentService` | `sendConversationCommandV4`，信封的 `type` 是 `sendText`、`payload.requestedDelivery` 是 `startNow` | `send` 带 `interrupt` 时打断当前这一轮立即发指令 |
| 窗口存储 | ZCode 工作区窗口 | `localStorage` 的 `zcode-v4-client-id:v1` | 会话命令信封的 `clientId`，宿主只收这个窗口的 |
| 快照字段 | `getTaskSnapshot` | `meta.mode`、`meta.status`、消息的 `durationMs` | 显示的模式、任务状态、一条回答写完没有 |
| 会话字段 | `readSession` | `settings.mode.current` | 代理实际用的模式（`session.mode` 可能是旧值） |
| 模式值 | 两个服务 | `yolo`、`build` | 界面上的「完全访问」「变更前确认」 |
| 启动参数 | `ZCode.exe` 的第二个实例 | `--open-workspace <目录>` | 让正在运行的 ZCode 把窗口切到这个工作区 |
| React 树 | ZCode 工作区窗口 | 组件 `memoizedProps.activeWorkspacePath` | 读窗口当前的工作区，核对切没切成 |
| 命令行 | gwb-mcp 的命令行客户端 | `<home>/node_modules/@godcreator/gwb-mcp/bin/client.mjs --home <home 名> --timeout <毫秒> run zcode.status <JSON>` | 等待脚本 `dist/wait-round.js` 回到本 home 的 MCP 入口查这一轮做完没有 |
| 内核字段 | 内核 | `gwbKernel.dataDir` | home 目录：拼出等待脚本与命令行客户端的路径，目录名就是 home 名 |
