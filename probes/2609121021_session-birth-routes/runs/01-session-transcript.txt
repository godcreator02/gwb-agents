# 结论：分三层——能点到、早就在开、但你要的那扇门另有钥匙

**TLDR：**「点开一个新会话」我今天就能做到（computer-use 直接操作左侧栏）；但取证后发现更本质的事实——**agent 开新会话这件事天天都在发生**（每次派子代理就在本机铸造一条新会话），你真正要的是「开一条**人可见、可点进去、可 resume 的主会话**」，那是一道宿主的门，目前的钥匙有三把，各有利弊。

## 取证到的事实

- ZCode 是 Electron 应用，正在运行（pid 69200），computer-use 看得见它——GUI 路今天可走。
- 本机注册了 **`zcode://` 协议**，接单的就是桌面版 `ZCode.exe`。这是宿主留给外部的 deep-link 通道，但它认不认「开新会话」之类的命令形态，没验证。
- **没有 CLI**：PATH 上没有 `zcode`，`.zcode\cli` 是数据目录不是发行版；会话本体在 `exec\sess_*`、索引在 `db.sqlite`。
- 那个目录里躺着四五十条 `sess_*` 主会话、上百条 `sess_subagent_agent_*`——**子代理就是会话**，同一个库、同一种 id（`ReadSessionContext` 都能读）。宿主把它们按命名分类，大概率左侧栏只列前一类。

## 各条路的账

| 路 | 今天可行 | 稳定性 | 返回通道 |
| --- | --- | --- | --- |
| GUI 点左侧栏（computer-use） | 是 | 脆：像素无语义 | 得自己搭（约文件 / 猜 sess id） |
| `zcode://` deep link | 未验证 | 若认命令则稳 | 看命令形态 |
| 派子代理（已有机制） | 是 | 稳 | 完整：TaskOutput 收结果 |
| 伪造 `db.sqlite` / `exec\` 条目 | 冻结中，且永远是坏主意 | 死路：第二份真相 | — |
| 给 ZCode 提「申请主会话」命令 | 不是本会话能落的事 | 最稳，可带守卫 | 可设计 |

GUI 路具体有四笔账：一是**抢焦点**——点完新会话，你的屏幕跳到那个空会话，我这条退到后台，你回来看不到我的回答（至少要「收尾时才点」的时序纪律）；二是**像素没有语义**——UI 一改版点击就落空，这跟 gwb 那边「端口没有语义、敲错一位落在另一个现场」是同款判例，而且 Electron 的无障碍树常露不全，露不全就只能走前台坐标点击，更脆；三是**开出来是空的**——还得配套往输入框注入第一句 prompt，每步都是脆弱点；四是**没有返回通道**——它干完活的结果怎么回到我手里，得另想办法。

`zcode://` 是最像「正门」的候选：如果它认某个开新会话的命令，`Start-Process "zcode://…"` 一行就是干净、不抢语义的开工方式。验证只要试一枚（或翻 `resources` 里的路由表），但那是动手，等你解锁。

## 关键反问：你要新会话图的是什么？

1. **只是并行分身、结果要回到我手里** → 子代理已经完整够用（后台跑、完成通知、TaskOutput 收结果），不必动宿主 UI。
2. **要人能看见、随时插手、事后 resume 的独立现场** → 才需要真·左侧栏会话；那值得先花五分钟验证 deep link 认不认，认了它就是最优解，不认再拿 GUI 点击当权宜。
3. **要让「开新会话」成为可编排的一环**（比如一条流程自动铺开 N 个现场）→ 必须走有合同的路（deep link 或提需求）并配守卫——谁付 token、数量上限、防递归繁殖——GUI 点击撑不起编排。

顺带一句本质：左侧栏是宿主开给人的作业面，agent 往里塞会话等于往人的桌面上堆东西。真到要长期用的那天，正路大概率是给 ZCode 提一枚带守卫的「申请主会话」命令，而不是让 agent 从窗外爬进去。

上面全部是只读取证加分析，没动任何东西。要动手验证 deep link、或演示一次 GUI 点击，等你一句 go。

## 挖出来的机制（比实验本身更值钱）

- **桌面端的每个会话就是一支子进程**：`zcode.cjs app-server --stdio --surface desktop`，插件走 `__zcode-plugin-host`——进程树里看得一清二楚。CLI 和桌面端是同一个内核家族（CLI 0.16.5 / 桌面 3.11.2，有版本漂移，这是 CLI 路的脆弱点）。
- **CLI 路有个隐蔽的配置坑**：`~\.zcode\cli\config.json` 里 `model.main` 必须是字符串引用 `"builtin:bigmodel-coding-plan/GLM-5.3"`，配套一个只含 `kind+options` 的最小 provider def；从 `.zcode\v2\config.json` 原样抄全量 provider 块会被 strict 的 models 校验**整份静默否决**，报错仍是「Model config is missing」，极难排查。
- **Electron 的无障碍树平时是空的**（只有窗口按钮），一次真实交互后整个激活（155 个元素全语义可见）——所以 GUI 路实际比预想能用：先一次坐标点击唤醒，之后连侧栏条目都能按元素点。但往输入框 set-value 会被 React 状态无视，得走「点击聚焦 + 窗口级键盘」。
- exec 目录是懒建的：CLI 会话和纯对话会话都不占 `exec\sess_*`，跑过 Bash 才有；判会话出生要看 db.sqlite 和 rollout，别只盯 exec。

## 三条路各干什么用

- **要并行分身、结果回到我手里** → CLI 是最优解：`--prompt` 出生、stdout 收结果、`--resume` 迭代驱动，全程无 GUI、无焦点扰动。它不进左侧栏——按你的用途这反而是优点（不往人的作业面上堆东西）。
- **要人看得见、到点自动跑** → CronCreate：宿主自己执行、左侧栏定时任务分组一等公民，这是唯一「官方认证」的 agent 侧开会话通道。
- **要立刻出现在普通会话列表里** → 目前只有 GUI 路一条道（今天已验证到底）。GUI 路的纪律：干完活把视图切回去（我已切回你原来那条「gwb内核与插件仓库docfirst文档升级」）。
